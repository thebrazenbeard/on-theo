# Ifá Binary Confirmatory Protocol — Hostile Review V1

## Verdict

Can this protocol produce a real null result?

YES.

Is it historically identical to traditional Ifá?

NO.

Is that acceptable?

YES, if it remains labeled MODERN_STRUCTURAL_ANALOGUE.

## Attack 1 — the randomized mapping solves one problem by reducing historical fidelity

Randomizing target labels to sides neutralizes raw side bias.

Good science.

But it is a modern control.

Do not later claim:
"traditional Ifá predicted hidden random bits."

It did not.

## Attack 2 — cryptographic commitment does not prevent all leakage

A hash proves the revealed payload matches the committed payload.

It does not prove:
- target generation was unbiased;
- plaintext never leaked;
- custodian was independent;
- implementation had no side channel.

Target custody needs its own audit.

## Attack 3 — 1551 trials will create fatigue and procedural drift

A manual ritual procedure repeated at this scale can change over time.

Required:
- planned sessions;
- operator workload limits;
- session metadata;
- calibration for drift.

If fatigue changes mechanics, model it or redesign before confirmatory data.

## Attack 4 — practitioner cues can survive target blinding

Even if nobody in the room knows the target, physical handling of the binary
alternatives can cue side placement or response.

Randomized digital mapping is cleaner than a target-aware human holder.

Prefer a custody implementation where no present person knows target or mapping.

## Attack 5 — a 55% minimum effect is a design choice

It is not source-derived.

A real but smaller effect would be missed.

That is acceptable if declared in advance.

Do not lower the effect threshold after a null result and call the same dataset
confirmatory.

## Attack 6 — one operator can fool you in either direction

A positive one-operator result might be:
- operator-specific;
- mechanical;
- fraudulent;
- accidental.

A null one-operator result does not characterize all practitioners.

The claim ceiling must remain protocol/operator-specific until replication.

## Attack 7 — hidden target selection must be boring

Do not use emotionally salient images, religious symbols, personally meaningful
targets, or targets with uneven base rates.

Use binary bits.

Anything else reintroduces interpretation.

## Attack 8 — no spiritual side-channel interpretation

During data collection:
- dreams;
- feelings;
- equipment glitches;
- repeated numbers;
- coincidences

are not secondary evidence.

If they were not preregistered, they are anecdotes.

## Attack 9 — success still does not identify the cause

837+ hits is not "contact."

First attack:
- randomizer;
- custody;
- logging;
- code;
- fraud;
- leakage;
- multiple testing;
- operator handling.

Only after those survive independent audit do we call it an anomaly.
